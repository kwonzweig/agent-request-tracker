# Using Request Tracker

Ask Codex to use Request Tracker in the current conversation, then describe the outcome you want. The agent records the request, its completion conditions and any choices or obstacles that arise. Continue speaking normally; you do not need to maintain the records yourself.

## The four tabs

| Tab | Use it to |
| --- | --- |
| Attention | Answer a pending choice, report progress on a blocker, or review new information and completed work. Cards stay expanded here. |
| Requests | Follow the outcomes you asked for. Expand a request to see its completion conditions and related work. |
| Cards | Find all cards, including postponed, resolved and dismissed items. Cards start collapsed. |
| History | Read what changed in an earlier exchange. Historical entries have no live reply controls. |

An empty Attention tab says **No action needed**. It does not mean every request is complete. Requests may also link to an existing task or ticket; those links do not synchronize it.

## Reply to a card

| Card | Action |
| --- | --- |
| Decision | Select a choice, write an answer under Other, or choose Later. |
| Suggestion | Accept an offered option, use Other, or choose Later. |
| Blocker | Perform the requested step and report what happened in chat or Comment. If offered, choose an alternative, Other or Later. |
| Q&A | Read the answer, then use × to mark it as read or Comment to follow up. |
| Note | Read the information, then use × to mark it as read or Comment to respond. |
| Complete | Review the result, then use × to mark it as read or Comment to follow up. |

Select a blue choice button or open Comment with the speech-bubble icon. **Send reply** submits your selected choices and comments together. Until then, they remain drafts. You can also answer directly in chat. If the card reports that storage or reply coordination is unavailable, use chat.

The × control means **Mark as read**. It saves that acknowledgment silently, without sending a chat message or starting the agent. The card leaves Attention after saving and remains in Cards. A failed save leaves it visible with an error. Other drafts stay untouched.

A Blocker has no Resolve button. Your report tells the agent what to check; the agent verifies whether the affected operation works before resolving it. Choosing an alternative permits that route without claiming the original obstacle was fixed.

## Postpone and return

Choose **Later**, then **Send reply**, when a choice can wait. After the agent records the reply, the card leaves Attention and remains in Cards. The choice is still unresolved. It may return to Attention when it blocks the next step, with an explanation of why it matters now.

Resolved cards leave Attention. The agent may record a card as Dismissed when it no longer applies, such as a connection request made unnecessary by a different input source.

When a request becomes Done, its Complete card appears in Attention. Marking that notification as read does not change the completed request. If the request reopens and is completed again, it gets a new notification.
